## 核心项目 EMA 一句话（30 秒，约 110 字）

EMA 全称 Engineering Memory Agent，一句话讲就是把研发过程中的代码、Git 历史、技术决策、故障经验，自动提取成结构化的长期记忆，让团队可以跨时间、跨人检索复用。

它解决的核心痛点是：**团队的知识存在人脑和聊天记录里，人走了知识就没了**。我做的是把这个过程自动化——不是写 wiki，而是从工程活动里自动沉淀。

## EMA 的三个技术亮点（2 分钟，约 440 字）

这个项目我从 0 到 1 独立完成，技术上有三个我比较得意的点：

**第一个是记忆系统的去重和冲突检测**。我设计了四级相似度分级：相似度 0.92 以上直接合并，0.75 到 0.92 之间调 LLM 检测是否矛盾，矛盾就走人机协同让用户仲裁，不矛盾就补充关联；0.6 到 0.75 插入新记忆但建立关联；0.6 以下才算全新。这样既能去重，又不会把矛盾信息粗暴合并掉。每个相似度阈值是经过调参的，0.92 是实测下来"几乎是同一条"的边界。

**第二个是艾宾浩斯衰减加权检索**。我借鉴了遗忘曲线，给每条记忆一个 decay_factor，公式是 R 等于 e 的负 t 除 S 次方，t 是距上次召回的小时数，S 等于 1 加召回次数乘 2。检索时排序用"相似度乘 decay_factor"，频繁被问到的记忆衰减得更慢，长期没人问的自然沉底。这个设计让记忆库能自我演化，不用人工清理。

**第三个是用 LangGraph 手动搭 StateGraph 而不是用预建 Agent**。我有两个 HITL 卡点：写操作前审批、记忆冲突时仲裁。用 LangGraph 的 interrupt 和 PostgresSaver 实现跨重启的对话恢复。没用 create_react_agent 是因为它是个黑盒，HITL 的插入点不好控制。
